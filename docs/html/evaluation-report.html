検証で出た不具合と修正結果

検証で次の6件を確認しました。発生条件を再現して修正し、再実行と復旧後の動作まで確認しています。

1. 監視フォルダーの表記差で、再試行やロックの扱いが変わる

検証で出た不具合
同じフォルダーでも、パス末尾の区切り文字の有無によって記録先とロックが変わる状態でした。以前の再試行ファイルを処理できず、二重起動を防げない場合がありました。
修正内容
同じフォルダーを同一のパスとして扱うよう統一しました。旧表記の配信記録と再試行ファイルを引き継ぎ、旧表記で起動したプロセスともロックを共有します。
再検証の結果
末尾の区切り文字を変えて起動し、記録の引き継ぎ、再試行、二重起動の防止を確認しました。保存先で競合した場合も、ファイルを保持して停止します。 解消を確認

根拠　修正前の失敗記録、修正後の起動・パス確認

2. 取得先のパスが正常でも、ファイルの取得を拒否する

検証で出た不具合
監視フォルダーのパス末尾に区切り文字があると、正常な取得先を範囲外と判定しました。FTPでの受信が失敗する状態でした。
修正内容
パスの区切り方をそろえ、監視フォルダー内かどうかを正しく比較するように修正しました。
再検証の結果
末尾の区切り文字の有無、フォルダー構造の保持、正当なファイル名の4条件で取得できることを確認しました。保存先の逸脱防止も維持しています。 解消を確認

根拠　取得4条件の確認結果

3. 旧ファイルの配信後も、同名の新ファイルを配信できない

検証で出た不具合
成功後も原本を残す設定では、配信済みの旧ファイルが再試行領域に残る場合がありました。同名の新ファイルを監視フォルダーへ置いても、処理を先送りし続けました。
修正内容
配信済みの旧ファイルとENDを保持用フォルダーへ保管します。新ファイルの配信を再開でき、保管中に停止しても次回に続きを処理できます。
再検証の結果
旧ファイルを残す設定と削除する設定の両方で、新ファイルが全宛先へ届くことを確認しました。ENDの有無と保管中の中断・再開も確認済みです。 解消を確認

根拠　同名ファイルの配信・復旧結果

4. 取得後に削除が失敗すると、次回の処理で削除を再開できない

検証で出た不具合
リモートのEND削除後にデータ削除が失敗すると、データだけが残りました。次回はENDがないため対象から外れ、削除を再開できませんでした。
修正内容
データとENDの削除状況を保存します。次回バッチは記録を確認して削除を再開し、別の内容へ差し替わったファイルは保持します。
再検証の結果
ENDの転送設定を変えた条件でも、削除失敗後の再実行で後処理が完了しました。データを再取得せず、差し替えられた新ファイルを削除しないことも確認しています。 解消を確認

根拠　取得後の削除再開結果

5. SFTPへ一斉に接続すると、一部の接続が拒否される

検証で出た不具合
16並列の測定で認証前の接続が集中し、サーバーから切断されました。再試行上限1回の条件でもバッチが失敗しました。
修正内容
同じ宛先への接続確立が同時4件までとなるよう、開始タイミングを調整しています。接続後のファイル転送は、設定した並列数で実行します。
再検証の結果
サーバー側の接続制限を変更せず、16接続の一斉開始を3回確認しました。大容量の追加測定でも1・4・8・16並列を各3回実行し、全件成功しています。 解消を確認

根拠　修正前の接続失敗、修正後の大容量測定

6. プログラム終了時に、エラーメールが届かない

検証で出た不具合
送信待ちの通知があるままプログラムが終了しました。通知上限5通の試験で、SMTP側の受信が0通になる現象を確認しました。
修正内容
プログラム終了時に通知処理が呼び出されるよう、通知機能の登録方法を修正しています。終了時には送信待ちの通知を処理します。
再検証の結果
通知上限ありでは5通、上限なしでは61通を終了前に受信しました。応答の遅いSMTPでも通知が届き、送信先が拒否した場合も原本を保持して終了します。 解消を確認

根拠　修正後のSMTP確認結果
