# SFTP接続確立上限の検証結果

2026-10-02にWindowsの製品クライアントで確認しました。専用状態では上限8件でパスワード認証・鍵認証の計640回がすべて成功しています。共用状態では8件で接続拒否が発生したため、既定値は4件を維持しました。上限は`Transfer.SftpMaxConcurrentHandshakes`で1～16件に変更できます。

## 測定条件

同じPCの試験用OpenSSH 10.3p1へ、16件の接続要求を一斉に出しました。各接続で1KiBを送信し、SHA256一致と削除を確認しています。接続失敗を再試行で隠さないよう、比較用プローブでは再試行していません。

パスワード認証は上限1・2・4・6・8・12・16件を各20回確認しました。認証前の接続を4本保持した条件では、上限4・6・8・12・16件を各10回確認しています。Ed25519の鍵認証は4件・8件を各20回確認しました。合計230回、3,680件の接続要求です。

サーバーの設定は変更していません。`sshd-effective-config.txt`に実際の設定を保存しました。MaxStartupsは10:30:100、LoginGraceTimeは120秒です。OpenSSHの[MaxStartupsの仕様](https://man.openbsd.org/sshd_config#MaxStartups)に従い、認証前の接続が集中すると接続が確率的に拒否されます。認証済みの転送接続数を制限する設定とは区別してください。

認証待ち接続は試験の間だけ4本を保持しました。100秒以内に測定を終え、保持接続がLoginGraceTimeで消えた結果を集計に混ぜないようにしています。試験用の保持接続を終了した後は、所有するサーバーだけを再起動し、次の鍵認証・通常起動試験へ進みました。接続元のペナルティ設定も変更していません。

## 結果

| 接続確立上限 | 専用状態の接続確立時間 | 専用状態の失敗 | 認証待ち4本がある状態の失敗 |
|---|---:|---:|---:|
| 1件 | 3.859秒 | 0 / 320 | 対象外 |
| 2件 | 2.102秒 | 0 / 320 | 対象外 |
| 4件 | 1.101秒 | 0 / 320 | 0 / 160 |
| 6件 | 0.836秒 | 0 / 320 | 0 / 160 |
| 8件 | 0.623秒 | 0 / 320 | 8 / 160 |
| 12件 | 接続拒否あり | 12 / 320 | 28 / 160 |
| 16件 | 接続拒否あり | 36 / 320 | 37 / 160 |

時間は16件の要求を出してから、最後のSFTP接続が使用可能になるまでの中央値です。接続枠の待機、鍵交換、認証、SFTP初期化を含み、ファイル転送・内容照合の全件完了時間は含みません。失敗がある条件の時間は推奨値の比較に使っていません。JSONのp95は観測値を上へ切り上げる方式で算出しています。

専用状態の8件は4件より接続確立時間が約43%短くなりました。鍵認証でも4件1.090秒、8件0.618秒で、各320件すべて成功しています。接続を再利用するため、この改善は主に初回の接続と再接続で得られます。

共用状態では4件・6件が全160件成功し、8件は160件中8件が失敗しました。他の利用者の認証待ち件数が変わる運用を考慮し、既定値を4件にしています。6件は中間の選択肢、他の認証処理が重ならない専用先では8件を推奨します。

通常の製品起動でも、転送16並列のまま、接続上限4件・8件のパスワード認証と8件の鍵認証を確認しました。各条件で32件を16接続で転送し、全件の内容照合が成功しました。再試行0回、終了コード0、原本残存0件です。

## 記録と再実行

`results/trials.json`と`results/key-auth/trials.json`に全接続の結果を収録しました。`summary.json`はその集計です。`batch-smoke.json`と各通常起動ログには設定バインド・Worker・接続再利用の確認結果を保存しています。`windows-release.trx`は全451件成功、失敗0件、スキップ0件のWindows回帰テスト結果です。

`results/source-hashes.json`と`results/measured-sources/`は測定に使用したソースの写しです。採取後、再実行スクリプトの再試行ログの集計式を製品ログに合わせて修正しました。収録ログを正しい集計式で再確認し、再試行0回という結果は変わっていません。

Docker、.NET 10、Python 3があるWindows環境で、リポジトリのルートから実行できます。

```powershell
docker pull atmoz/sftp:alpine
python docs/evaluation/2026-10-02-sftp-auth/run_probe.py
```

出力先は未作成の`.audit-results/sftp-auth-rerun`です。別の出力先を使う場合は、`.audit-results`配下の未作成フォルダーを`--output`で指定してください。再実行ではその時点の`alpine`イメージを使うため、記録済みのイメージIDも確認してください。今回のイメージと実行環境は`results/environment.json`に保存しています。

採取済みの結果と資料の数値は、次のコマンドで確認できます。

```powershell
python docs/evaluation/2026-10-02-sftp-auth/verify_results.py
```

試験用のファイル、秘密鍵、所有するコンテナは削除済みです。後始末の結果は`results/cleanup.json`に収録しました。10月1日の大容量測定と本番での手動確認の記録は、その実施時点の証跡として保持しています。
